# 실제 과제에 적용하는 순서

5단계까지 제공하는 공개 지식의 사용 절차다. 실제 문제·입출력 계약·평가 기준을 먼저 읽는다.
아래 사례는 자체 작성한 합성 상황이며 SK하이닉스 출제 예상이나 Probe 동작 설명이 아니다.

## 제공 Codex에 입력할 요청

> 반입한 하네스 저장소의 knowledge/semiconductor/README.md와 application-playbook.md를 읽어줘. 실제 과제의 목표·입출력·평가 지표·제약부터 확인하고, index.jsonl에서 관련 개념만 찾아 적용해줘. 데이터의 행 단위·키·단위·정답 가용 시점·분할·누수 위험을 점검한 뒤 작은 기준선부터 구현해줘. 같은 검증 조건에서 개선을 비교하고 제출 파일을 실제 계약대로 검사해줘. 사용한 개념 ID, 실제로 실행한 명령과 결과, 확인되지 않은 가정을 근거 문서에 남겨줘. 공개 예제 숫자를 과제의 사실로 쓰지 마.

하네스 설치기는 이 지식 폴더를 과제 루트로 복사하지 않는다. 반입 저장소를 유지하고
현재 지식 폴더의 실제 경로를 작업 기록에 남긴다. 본문 조회에는 별도 패키지나 네트워크가 필요 없다.

## 과제를 받은 뒤 확인할 것

| 순서 | 구체적으로 남길 결과 | 연결 |
| --- | --- | --- |
| 1 | 목표·예측/분석 시점·입력/출력 스키마·실제 채점 지표·시간/의존성 제약 | D12 |
| 2 | 한 행의 단위, 키, 단위/시간대, 결측 의미, 결합 관계, 검사 분모 | D01–D03 |
| 3 | 질문에 필요한 소자/공정/메모리/패키징 개념과 적용 조건 | F/P/M/H ID |
| 4 | 비교 집단·시간/그룹 분할·라벨 지연·특징 가용 시점 | D06–D08 |
| 5 | 단순 집계 또는 기준선, 고정 검증 구간과 지표 | D04/D05/D09–D11 |
| 6 | 한 가지 개선의 같은 조건 비교, 실패 사례·단위·불확실성 | D03/D06/D09–D11 |
| 7 | 출력 ID/중복/누락/열/값/순서, 재실행 명령과 실행 결과 | D12 |

실제 과제가 예측 문제가 아니라 설명·집계·원인 분석이면 불필요한 모델을 만들지 않는다.
진단 시점에 알려진 결과를 쓰는 분석과 그 결과를 미리 예측하는 모델은 가용 입력이 다르다.
규격·평가 지표·판정 규칙이 제공되지 않으면 가정으로 적고 결과에 미치는 영향을 설명한다.

## 문제 유형별 시작 경로

| 상황 | 읽기 경로 | 먼저 막을 오류 |
| --- | --- | --- |
| lot/wafer 수율이 낮아진 이유 | P04/P13 → D01/D02 → D03/D06 → H15 | 재검사 중복·제품 구성 교란·검사 분모 차이 |
| CD/막 두께가 규격에 맞는지 | P06/P07/P10/P12 → D04/D05 → D10 | 관리한계와 규격 혼동·측정 산포·비정규 해석 |
| 센서로 다음 run의 불량 예측 | P04 → D01/D07/D08 → D09/D11 | 미래 도착값·전체 run 특징·그룹/시간 누수 |
| wafer map의 edge/ring 이상 | F09/P12 → D01/D06/D03 → H15 | 회전·좌표·미검사 영역·공간 상관·성급한 원인 확정 |
| 메모리 오류 증가 | M04/M10/M11/M13 → D01/D03/D07 → H10/H15 | bit/개체/시간 분모 혼합·ECC 전후 혼동 |
| HBM 대역폭·온도·접합 불량 | F07/F11/M05 → H01/H02/H07/H08/H09 → D06/D10 | 적층 수를 대역폭에 중복 곱함·열 경계조건 생략 |

예: 가상 1024-bit·4 Gbit/s 인터페이스의 피크는512 GB/s이고, 같은 경계에서 실측320 GB/s면
비율은62.5%다. 코어8개 적층을 다시 곱하지 않는다. 워크로드·전송량 집계·온도·전력 조건을
받기 전에는 나머지 차이를 특정 고장 때문이라고 결론 내리지 않는다. 근거: F07/F11/M05/H01.

## 저장소 자체 검증

반입 저장소 루트에서 Python 3.9 이상이 있다면 실행한다. Python은 본문을 읽는 데 필요하지 않다.

```bash
python3 knowledge/semiconductor/verify.py
```

다른 작업 폴더에서는 위 스크립트의 실제 절대 경로로 실행한다. 외부 Python 패키지·API 키·
네트워크·환경 설정 변경 없이 동작하며 원본 과제 파일을 읽거나 수정하지 않는다.
`-O` 또는 `PYTHONOPTIMIZE` 최적화 모드는 검증을 생략할 수 있어 거부한다.

검증은 다음 두 부분이다.

- 65개 본문/색인·84개 출처의 구조, 내부 링크·관계, 62개 검색어, 코드에 고정한 교육용 계산 fixture 91건.
  본문 숫자 전체의 자동 대조가 아니며, 일부 예제만 본문 문자열과 연결한다.
  외부 URL의 현재 접속 가능성이나 주장 전체의 정확성을 자동 검증하는 것은 아니다.
- [합성 적용 검사](checks/application_checks.py) 16개: 재검사 수율/결합, 마지막 판정,
  결합 키 오류, Wilson 경계, SPC/Cpk, 제품 구성 교란, 가용 시점 결합,
  그룹/시간 분할, 학습 전용 대치, 희소 불량 분류, 회귀 단위,
  알람 이벤트 집계, HBM 단위 연결, 관측 처리량/전송률의 초기 지연 중복, 절대/상대 유전율, 제출 ID/값 검증.

합성 적용 함수는 검사 예제를 위한 작은 구현이다. 실제 파일 형식·결측·대규모 데이터·분할
규칙에 그대로 쓸 분석 라이브러리가 아니다. 실제 모델을 학습하거나 장비를 시뮬레이션하지 않는다.
PASS는 패키지와 이 예제들의 통과이며 실제 과제 점수·Probe 호환성·시간 제한 통과를 뜻하지 않는다.
