# 문제 적용·기준선·근거·재현·제출

ID: `D12` · 단계 5 · 출처 확인: 2026-10-30

과제 계약을 먼저 읽고 작은 기준선부터 제출 형식까지 연결한다.

## 원리·적용 절차

공개 방법론을 바탕으로 이 패키지가 제안하는 절차: 입력/출력·지표 확인 → 데이터 계약 → 개념 조회 → 분할 고정 → 기준선 → 한 가지 개선 → 동일 조건 검증 → 제출 검사. 실제 과제 안내가 우선이다.

## 지표·공식과 적용 조건

코드·데이터 버전, 실행 명령, 분할 ID, seed(사용 시), 전처리·모델·임계값, 지표·단위, 출력 스키마를 남긴다. seed 하나가 모든 환경의 동일 결과를 보장하지 않는다.

## 직접 만든 적용 예제

가상 제출 대상 ID가 [a,b,c]라면 예측3행이라는 확인에 더해 ID 유일성·누락·추가 ID·NaN·열 이름·순서를 검사한다. [a,a,c]는3행이어도 실패다. 정렬 요구는 과제 계약을 따른다.

## 혼동·적용 한계

기준선보다 점수가 낮으면 실패를 숨기지 않고 근거를 남긴다. 합성 예제 통과는 실제 데이터 정확도·시간 제한·Probe 호환성 통과가 아니다. 라이브러리는 제공 환경을 확인한 후 사용한다.

## 과제에서 확인할 질문

- 다른 실행에서도 같은 입력에서 출력과 검증 근거를 재현할 수 있는가?
- 제출 스키마·허용 입력·평가 지표를 실제 안내와 대조했는가?
