# 하네스 공학 원칙

원본 하네스의 제0원칙과 변경 규약을 Codex 실행 구조로 이식했다.

## 제0원칙 — 코드는 사람을 위한 것이다

1. 한눈에 이해되는 응집된 단위로 나눈다.
2. 이름은 계약이다. 이름만으로 역할이 드러나야 한다.
3. 실제로 바뀔 축은 계약 뒤에 구현을 숨겨 교체할 수 있게 한다.
4. 모듈이 바뀌는 이유는 하나로 유지한다.
5. 추측성 인터페이스·구현 하나뿐인 추상·과분할을 피한다.

## 변경 규약

- 바뀐 줄은 요청이나 그 구현·검증에 필요한 변경으로 설명할 수 있어야 한다.
- 요청 밖 코드·주석·포맷 개선을 섞지 않는다.
- 내 변경이 만든 미사용 코드는 정리한다. 기존의 무관한 문제는 보고한다.
- 범위를 좁게 유지한다는 이유로 필요한 연결·검증·설명을 생략하지 않는다.

## 스타일 정본과 글쓰기

스타일 판정의 우선순위는 Google 스타일 가이드 → 제0원칙·변경 규약 →
프로필의 불변식 → readable-writing → ECC·개인 취향이다.
과제의 필수 동작·플랫폼 제약·상위 지시는 스타일 선호로 바꾸지 않는다.
Google이 다루지 않는 영역은 다음 기준과 기존의 일관된 관례를 따른다.

코드·문서 작성과 검수 전에 `.agents/skills/google-styleguide/SKILL.md`를 읽고
작업 언어의 원문을 연다. 번들 원문과 언어별 URL 매핑을 사용하며 기억으로 인용하지 않는다.
설치되지 않았으면 반입본 `template/`의 같은 경로를 읽는다.
정본에 접근할 수 없으면 미확인으로 표시하고 근거 없는 스타일 지적을 하지 않는다.

developer는 스타일 검사를 직접 실행한다. reviewer는 원문 조항과 검사 결과를 대조한다.
plan-reviewer는 새 언어·문서 형식의 정본 매핑을 확인한다.
설명 역할과 메인은 `.agents/skills/readable-writing/SKILL.md`도 읽는다.
용어의 첫 등장 풀이·핵심 선행·독자 수준·일관된 이름·주석의 이유 설명을 적용한다.

전체 설치의 `harness.py verify`는 Google Go 포맷 검사와 실제 과제 검사를 수행한다.
기존 checks 슬롯이 보존돼도 스타일 검사는 빠지지 않는다. 직접 읽기에서는
`python3 -B <반입본>/template/.agents/skills/google-styleguide/scripts/check_style.py
--root <과제 루트>`를 한 명령으로 실행한다. 검사기는 파일을 수정하지 않는다.
Go가 없으면 적용 대상 없음, gofmt 부재·실행 오류는 미검증이다.
포맷 위반과 실행 불가를 구분하고 다른 언어의 검사를 통과했다고 확대하지 않는다.

## ECC

ECC의 코딩·테스트·보안 기준은 Skill의 `references/ecc-quality.md`를 읽는다.
이 원칙과 프로필을 우선 적용하고, 언어·과제와 무관한 기준을 강제하지 않는다.

## 검증과 설명

실행한 명령과 성공·실패를 구분한다. 읽어본 것과 실제 동작을 확인한 것을 구분한다.
계획·검수는 확인한 경로를 근거로 삼고, 없는 실측·독립 리뷰·완료 사실을 만들지 않는다.
선택 이유·대안·실행 흐름·한계를 응시자가 자기 말로 설명할 수 있게 전달한다.
