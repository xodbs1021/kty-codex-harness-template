# 과제 판단과 검증 근거

실제 과제 시작 뒤 채우는 프로젝트 슬롯이다. 재설치 시 보존한다.
공개 데모의 항목·점수를 실제 과제의 요구나 배점으로 옮기지 않는다.
중요한 변경 시 아래 행만 갱신한다. 작업 전체를 복제하는 일지는 필요 없다.
과제가 지정한 제출 문서가 있으면 관련 결론을 그 문서에도 반영한다.

## 요구와 확인

| ID | 사용자·업무 목표와 필수 동작 | 확인 출처 | 성공·실패를 구분할 관찰 | 상태 |
| --- | --- | --- | --- | --- |
| R1 | 미확인 — 실제 과제에서 작성 | README 경로·절 또는 업무 담당자 답변 | 미확인 | 미확인 |

상태는 미확인·진행·충족·부분 충족·미검증·제외를 구분한다.
추측은 요구로 확정하지 않는다. 답변이 없으면 가정과 영향, 보수적 처리 방향을 적는다.

## 중요한 판단

| 관련 ID | 쟁점·대안과 선택 이유 | 판단 출처 | 영향·남은 한계 |
| --- | --- | --- | --- |
| 미작성 | 실제 선택 시 작성 | 응시자 직접 지시 / 담당자 확인 / AI 제안·응시자 미확인 | 미확인 |

AI가 제안한 결정을 응시자 결정으로 바꾸어 적지 않는다.
직접 확인·수락했다는 응시자 발언이나 행동이 있을 때만 그 근거를 추가한다.

## 구현과 관찰 근거

| 관련 ID | 현재 구현 위치 | 확인 방법·입력 | 실제 결과·근거 위치 | 확인 주체·남은 확인 |
| --- | --- | --- | --- | --- |
| R1 | 미확인 | 미실행 | 미검증 | AI 실행 / 응시자 수동 확인 / 미확인 중 실제 상태 |

`verification.json`은 명령 성공과 파일 지문만 증명한다. 요구별 충족 판정은 실제
입력·출력과 연결한다. 실패→수정→재실행이 있었다면 그 결과도 구분한다.
필요한 실제 출력·수치만 남기고 비밀값이나 전체 데이터를 복사하지 않는다.

## 작업 단계 종료 전 설명

- 실제 요청 → 주요 처리 경로 → 결과, 중요한 이유와 포기한 대안:
- AI에 맡긴 범위·수정한 파일과 응시자가 직접 결정·확인한 범위:
- 반례·오류 처리·측정 결과와 미해결 한계:
- 응시자 이해 확인: 미확인. AI 설명 생성만으로 이해 완료로 바꾸지 않는다.
- 지정 제출물의 경로·저장 상태 / 실제 제출: 미확인. 제출은 응시자가 직접 확인한다.

후속 서술형 단계가 시작되면 AI 설명·문제별 답안 생성·보조를 종료한다.
