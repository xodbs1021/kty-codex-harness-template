# 과제 API에 적용하는 기준

이 문서는 Google AIP를 서비스 과제에 적용하기 위한 KTY의 해석·검토 절차다.
원문을 대체하지 않으며 번호별 규범은 source-map에서 선택한 원문을 읽어 확인한다.

## 계약의 우선순위

과제의 명시적 요구와 기존 외부 계약을 보존한다. 미정인 설계에는 Google AIP를 기본 근거로 쓴다.
상충하는 기존 명세·테스트는 충돌을 드러내 해결하며, 테스트가 있다고 명시적 요구를 덮어쓰지 않는다.
예를 들어 과제가 `GET /`의 인사말이나 고정된 JSON·상태 코드를 요구하면 그대로 유지한다.
리소스형 CRUD 예시를 보고 새 `/v1/...` 경로로 대체하거나 필수 응답을 감싸지 않는다.

원문은 Google의 RPC/Protobuf/HTTP 매핑에 관한 구체 규칙도 포함한다. HTTP/JSON 서비스라면
언어와 무관한 계약 원칙을 채택하고, Proto 메시지·필드 번호·`google.api` annotation·
`google.rpc.Status` 의존성까지 임의로 추가하지 않는다. Google 형식을 채택한다면 그 매핑을
정확히 따르고, 다르게 적용하면 차이를 명시한다. 자체 JSON의 필드명 규칙과 Proto의
snake_case/ProtoJSON 매핑을 혼동하지 않는다. 내부 Python/Java/Go 심볼 스타일은 별개다.

## 판단과 검증에 연결

- **리소스·메서드:** 실제 사용자 동작을 자원과 표준 동작에 연결한다(121–136).
  새 API의 표준 동작과 custom 동작을 구분하고 기존 경로·메서드·응답과의 호환성을 확인한다.
  원문의 management-plane 강한 일관성 조건을 모든 데이터 처리에 무조건 확대하지 않는다.
- **입력·부분 수정:** 필수·선택·output-only, 누락과 `null`·0·false·빈 문자열의 의미를 정한다
  (134/140/149). 부분 수정에서 미지정 필드를 기본값으로 지우지 않는지 실제 반례로 확인한다.
  Proto update_mask와 일반 JSON PATCH 표현을 같다고 간주하지 않는다.
- **오류·권한:** 클라이언트가 구분할 오류 종류·상태·본문을 정한다(193/211).
  권한 없는 요청에 리소스 존재·내부 예외·비밀 정보가 새지 않는지 확인한다.
  인증 실패와 인가 실패를 구분하고 실제 채택한 HTTP/RPC 매핑으로 검사한다.
  공개 인사말 엔드포인트에 지침을 이유로 인증 시스템을 새로 붙이지 않는다.
- **목록·페이지:** 목록을 제공하면 페이지 상한·기본값·잘못된 입력·계속 토큰을 확인한다(132/158).
  158을 채택한 경우 0은 기본값, 음수는 오류, 상한 초과는 상한으로 제한하며,
  짧거나 빈 페이지라는 이유만으로 끝났다고 판단하지 않고 next_page_token을 따른다.
  다음 페이지에서는 page_size 변경은 허용하되 다른 인수는 유지한다.
  토큰은 권한 증명이 아니며 페이지마다 인가한다. 기존 offset 계약을 몰래 토큰식으로 바꾸지 않는다.
- **중복·경쟁·실패:** 관련 있을 때 재시도 안전성, 요청 ID 중복 제거, stale etag를 검토한다
  (154/155/194). 요청 ID를 받는 것만으로 중복 제거됐다고 하지 않는다.
  194의 자동 재시도 대상·오류를 원문에서 확인하고 모든 5xx나 POST를 자동 재시도하지 않는다.
  제한 횟수·시간/백오프 등 실행 정책은 과제 제약에 맞춰 정하고 실제 선택임을 밝힌다.
- **호환성:** 변경 전 클라이언트의 경로·필드·기본값·오류·동작을 깨는지 확인한다(180).
  필요한 버전 전환이 별도 요구가 아니면 새 버전 체계를 만들지 않는다.

검토 표는 필요한 행만 작성한다: `외부 계약 | AIP/절 | 적용·예외 이유 | 입력 → 기대 결과 |
현재 설계/코드·테스트 위치 | 실제 실행 결과 또는 미검증`.
범용 체크리스트를 채우기 위해 미사용 기능을 구현하지 않는다.
기존 테스트 도구와 권한 내에서 정상·잘못된 입력·관련 실패/권한/중복 사례를 검사한다.
계획된 테스트·기존 로그 확인·이번 직접 실행을 구분한다. 읽기 전용이면 디스크·캐시·DB를
수정하는 검사를 실행하지 않고 안전한 검사 결과와 남은 범위를 응답으로 반환한다.
