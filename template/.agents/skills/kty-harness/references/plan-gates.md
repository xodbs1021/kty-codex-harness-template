# 설계·계획 게이트

원본의 구조/세부 분류와 이월 계약을 Sol A/B에 적용한다.
설계와 구현 계획은 별도 pass이며 각 pass의 같은 상태를 두 독립 컨텍스트에서 검토한다.

## 분류와 종결

지적에는 설계/문서, 구조/세부, 심각도, 시나리오와 분류 근거를 적는다.
구조는 되돌리기 비싼 결정이다. 예: 동일성 기준·모듈 경계·이벤트 루프 점유·트랜잭션 소유.
세부는 구현에서 확인하기 쉬운 위치·조건·수치·반환값이다.
분류가 불명확하면 구조로 다루고, 세부로 낮추려면 근거를 남긴다.
운영 판단을 오도하는 문서는 단순 문구라는 이유로 심각도를 낮추지 않는다.

같은 pass의 같은 라운드에서 A/B 모두 구조 CRITICAL/HIGH가 없어야 다음 단계로 간다.
서로 다른 버전·라운드의 승인을 합치지 않는다. 미확정 CRITICAL도 차단이다.
세부 HIGH는 지우지 않고 아래 세 조건을 모두 만족할 때 구현으로 이월할 수 있다.

1. 원 심각도·시나리오·처리 책임을 통합 기록에 보존한다.
2. developer에게 착수 체크리스트로 전달한다.
3. 코드 A/B 입력에 같은 ID를 전달하고 각 항목의 해결·검증을 확인한다.

셋 중 하나라도 빠지면 이월된 것이 아니라 유실된 것이다. 이월 건수를 사용자에게 보고한다.
세부 CRITICAL은 미해결로 이월하지 않는다. MEDIUM/LOW는 부수 관찰로 요약하되
그것만으로 검토 라운드를 늘리지 않는다.

## 수정과 확인

각 지적을 수정·기록과 사유·이연과 귀속으로 처리하고 확인 pass에 전달한다.
후속 검토도 선행 결정의 존재·모순 여부·실제 반영과 조사 표명·불요 사유·근거 반영을 확인한다.
수정된 계약 전체와 필요한 주변 근거를 읽고 보고는 새 위반 위주로 한다.
구조 차단이 없어지면 반복 무지적 횟수를 채우지 않고 종결한다.
진전 없이 반복하지 않으며, 전면 라운드가 3회에 도달해도 구조 차단이 남으면
임의 4회차 대신 미해결 문제와 필요한 사용자 판단을 전달한다.

단독 지적의 교차 검증은 설계·계획 CRITICAL, 또는 기각하려는 HIGH에만 요구한다.
수용하는 HIGH는 수정·기록하며 별도 반박 호출을 의무로 늘리지 않는다.
코드 검토에서는 단독 CRITICAL/HIGH 모두 [교차 검증 계약](cross-verification.md)을 따른다.
