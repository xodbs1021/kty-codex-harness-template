# Probe 과제 수행 보완

실무 평가 과제를 시작하거나 제출 전 점검할 때 읽는다.
공식 공개 자료의 해석 근거는 패키지 저장소 `docs/probe-analysis.md`에 있다.
공개 데모는 설명용 예시다. 실제 요구·배점·도구 허용 범위는 현재 과제 안내가 정한다.

## 문제 정의와 업무 확인

- `.harness/task-evidence.md`에서 필수 요구마다 출처·성공 조건을 연결한다.
  기존 과제 문서에 같은 표가 있으면 그 문서를 정본으로 삼고 경로만 연결한다.
- 업무 담당자에게는 구현을 바꾸는 모호함을 묻는다. 질문 전에 README·데이터·기존 코드를
  확인하고 쟁점과 대안을 좁힌다. 화면 사용법은 Helper에 확인한다.
- 정상 동작 외에 업무상 실패를 정의한다. 예: 결제 결과가 늦을 때의 상태, 중복 요청,
  집계에서 빠진 데이터의 영향. 데모의 도메인이나 해법을 실제 과제에 가정하지 않는다.
- 질문은 묶어서 전달하고, 이미 확인한 것을 다시 묻지 않는다. 답이 없으면 가정과 영향을
  밝히고 되돌릴 수 있는 범위부터 진행한다. 확인받지 않은 가정을 사실로 승격하지 않는다.

## AI 위임과 실제 판단 구분

AI나 독립 역할에게는 목표·대상 파일·허용 변경·지켜야 할 계약·검증·중단 조건을 전달한다.
결과를 받은 메인은 diff와 근거를 확인하고 수용·수정·거절 이유를 기록한다.
역할 수나 프롬프트 길이를 평가 점수의 대용으로 삼지 않는다.

중요한 선택의 출처는 응시자 지시·업무 담당자 답변·AI 제안을 구분한다.
AI가 자율적으로 고른 결정을 응시자 주도 판단이라고 작성하지 않는다.
AI가 실행한 테스트, 응시자가 직접 본 미리보기, 독립 검수를 구분한다.
수동 확인을 기다리는 상태는 미검증이다. 지연되는 확인과 무관한 구현은 계속 진행한다.

## 요구별 검증과 반례

- 각 필수 동작에 현재 코드 위치와 실제 관찰을 연결한다. 테스트 통과만으로
  다른 요구까지 충족 처리하지 않는다. 실행하지 않은 UI·외부 연동은 남은 확인으로 적는다.
- 데이터 제외·보정·중복 제거·필터 변경은 필요할 때 행 수·합계 등 핵심 결과의
  전후 차이와 제외 이유를 실제로 측정한다. 의미 있는 차이가 없다면 그 결과도 적는다.
- 업무에 맞는 정상·경계·실패 입력으로 불변식을 확인한다. 예: 중복·재시도,
  빈 입력·누락값, 타임아웃과 부분 실패. 관련 없는 항목을 의무 테스트로 늘리지 않는다.
- 실패를 발견하면 입력·증상·수정·재실행을 연결한다. 실패 로그를 성공 기록으로
  바꾸거나 사후에 실행하지 않은 검증을 만든 기록으로 채우지 않는다.
- 영수증은 현재 파일 지문에서 명령이 통과했다는 제한된 근거다. 무시된 생성물,
  외부 서비스, 제출 화면의 상태까지 증명하지 않는다.
- 근거·제출 문서도 코드 지문에 포함된다. 기록을 완성한 뒤 최종 `verify`를 실행한다.
  그 뒤 문서를 고치면 다시 검증한다. 실행할 때마다 시각·지문을 문서에 다시 써서
  영수증을 무효화하는 순환을 만들지 말고, 상세 실행 시각은 영수증을 참조한다.

## 작업 종료와 본인 설명

과제 작업 단계 안에서 핵심 경로, 선택 이유·대안, 검증 결과·한계를 코드 위치와 함께
짧게 설명한다. 이해가 필요한 핵심 선택은 응시자가 자기 말로 설명하도록 확인을 제안한다.
답을 받지 못했으면 이해 상태는 미확인으로 남긴다. 답변을 대신 작성해 이해했다고 기록하지 않는다.

후속 서술형 단계에서는 답안 작성·설명을 보조하지 않고 AI 지원을 종료한다.
필수 제출 파일에는 과제가 요구한 실제 근거만 반영하고, 저장과 실제 제출을 구분한다.
문서 양을 채우려고 구현·검증 시간을 소진하지 않는다. 마지막 시간은 필수 경로 검증과 제출에 쓴다.
