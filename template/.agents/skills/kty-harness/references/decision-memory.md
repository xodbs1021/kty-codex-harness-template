# 결정·진행·검수 기록

원본 하네스의 기록 계약을 제공 과제 내부로 옮긴다. 외부 메모리·개인 vault·PR·push는
사용하지 않는다. 전체 읽기 전용이면 아래 내용을 대화에 반환하고 파일 기록으로 표시하지 않는다.
과제가 지정한 문서가 있으면 그 문서를 정본으로 쓰고 불필요한 문서를 추가하지 않는다.

## 단계 전환과 재개

단계가 바뀔 때 `.harness/work/progress.md`에 작업 식별자·현재 단계·완료 근거·
다음 행동·미해결 결정을 갱신한다. 재개는 실제 파일과 이전 근거를 대조한 뒤 필요한 단계만 잇는다.
새 작업을 시작하면 이전 실행과 검토 결과를 섞지 않는다. 쓰기 가능하면 이전 기록을
충돌 없는 `.harness/work/archive/<작업 식별자>/`에 보존한다. 과거 기록을 지우거나
새 작업의 승인·검증으로 재사용하지 않는다. 읽기 전용이면 대화에서 작업별로 구분한다.

## 중요한 결정의 기록

대안을 기각하고 구조·라이브러리·패턴·절차를 확정했거나, diff에 드러나지 않는 결정을
내렸거나, 사용자가 ADR(설계 결정 기록)을 요청하면 결정 시점에 기록한다.
자명한 선택과 작은 수정에는 별도 ADR을 강제하지 않는다.

먼저 프로필 9절·기존 결정의 관련 항목을 읽고 중복·충돌을 확인한다. 과제 지정 문서가
없다면 `docs/decisions/YYYY-MM-DD-<주제>.md`를 쓰며 기존 번호를 확인한다.
형식은 제목 `ADR-NNNN: <결정>`, Context(문제), Decision(결정),
Alternatives Considered(대안별 장점·단점·기각 이유), Consequences(이익·비용),
관련(선행 결정 또는 없음)이다. 메인이 작성하고 reviewer·auditor가 실제 결정과 대조한다.
시험환경 밖의 문서 저장·PR을 요구하지 않는다. 시간과 필수 제출 형식에 맞춰 짧게 쓴다.

## 반복 지적과 전문 역할 제안

검수 지적에는 출처 A/B 외에 경계면·불변식·제0원칙·품질·테스트·성능·접근성·국제화 등
해당 카테고리를 붙인다. 같은 결함을 A와 B가 보고한 것은 하나로 합친다.
과제 내부의 `.harness/work/review-counts.md` 또는 대화에서 수용한 지적만 집계한다.
기각·중복·재검토한 동일 지적을 새 사례로 세지 않는다.
전문 검수자가 없는 카테고리의 HIGH 이상이 서로 다른 사례로 3회 누적되면
해당 전문 역할을 추가할 필요를 사용자에게 제안한다. 과거 기록이 없으면 현재 확인 범위만 센다.
승인 없이 역할·전역 도구를 설치하지 않는다. 기존 제공 도구·공개 해법을 먼저 확인하고
시험 시간·권한 안에서 적용 가능한지 판단한다. 외부에 시험 지적을 검색어로 보내지 않는다.

## 설치본과 기준본 차이

설치·업데이트·작업 트리 이동·하네스 변경 시 실제 반입 패키지와 설치 manifest,
원칙·Skill·역할을 비교한다. 확인된 과제 사실과 보존 슬롯은 정당한 차이일 수 있다.
의도한 프로필 조정과 관리 파일의 누락·이전 버전·로컬 수정을 구분한다.
기준본을 확인하지 못하면 최신·동일이라고 말하지 않는다. 자동 덮어쓰기·권한 우회 없이
설치기의 충돌 보고와 허용된 병합 절차를 따른다.
설정 키·역할·검사 명령의 파싱 성공과 실제 활성화는 별도다.
이 확인은 Claude의 PreToolUse 가드와 같은 강제 기능이 아니다.
