# 수학·알고리즘 도구 선택과 검증

조사일: 2026-11-05. 공식 프로젝트 문서·저장소를 확인한 후보 목록이다.
고정 커밋·라이선스·확인 범위는 [math-tools.json](math-tools.json)에 있다.
이 문서는 재시험 주제 예측이나 모델 학습 결과가 아니다. 새로운 문제의 수학적 구조를 먼저 확인한다.

## 적용 시점

수식·그래프·제약·최적화가 핵심인 요구에서는 설계·계획·구현·리뷰 전에 이 문서를 읽는다.
역할마다 맡은 범위만 적용한다. 단일 지적 교차 검증에서는 해당 지적의 수학적 조건만 확인한다.
수학과 관련 없는 작업에는 솔버·MCP·실험 인프라를 추가하지 않는다.

1. 입력의 크기·단위·시간 범위, 결정 변수, 강제 제약과 선호 제약, 목적함수를 명시한다.
2. 기존 코드·설치 라이브러리·시간·언어·권한을 확인하고 가장 작은 실행 가능한 방법을 고른다.
3. 단순 기준선과 비교한다. 솔버 사용/미사용 이유를 요구와 실제 측정으로 설명한다.
4. 결과를 원래 요구 기준으로 독립 재계산한다. 솔버 모델에 제약을 잘못 넣으면 솔버가 성공해도 잘못된 답이다.
5. 실제 입력·명령·버전·상태·시간·목적값·검증 결과를 과제 내부 근거에 기록한다.

패키지 이름은 식별용이다. 이 목록은 자동 설치 목록이 아니다. 현재 프로젝트에 필요한 것만
호환 버전과 라이선스를 확인하고 기존 의존성 관리 방식에 맞춰 추가한다. 솔버를 사용한다고
언어를 교체하지 않는다. Go 등에서 바인딩·프로세스 연동이 필요하면 실제 제공 환경부터 확인한다.
이 라이브러리들의 직접 로컬 실행에는 별도 AI API 키가 필요 없다.

## MCP 후보 3개

MCP는 모델이 수학 도구를 호출하는 연결 방식이다. 수학 엔진이나 권한을 대체하지 않는다.
제공 환경에서 직접 라이브러리를 실행할 수 있으면 그 경로를 먼저 검토한다.
다음은 커뮤니티 서버이며 라이브러리 제작자가 공식 지원하는 MCP라고 단정하지 않는다.

### 1. mcp-sympy — 기호 수학 연결 후보

- [저장소](https://github.com/daedalus/mcp-sympy), MIT, 조사 커밋의 버전 0.1.0.
- `pyproject.toml`: Python >=3.11, SymPy >=1.13, FastMCP >=2.0.
- README는 전개·인수분해·방정식·미적분·행렬·정수론 도구와 `mcp-sympy` 실행 항목을 제공한다.
- 실행 진입점은 `tools.mcp.run()` 호출로 확인했다. 실제 호스트와 전송·기동 호환성은 시험하지 않았다.
- 기호 수학이 중심이고 MCP 등록이 허용될 때 검토한다. SymPy 직접 호출과 동일한 정의역·해 검증이 필요하다.

### 2. mcp-solver — 여러 제약 솔버 연결 후보

- [저장소](https://github.com/szeider/mcp-solver), MIT, 조사 커밋은 v4.1.0 구조다.
- Python >=3.13,<3.15 및 `uv`가 필요하다. 하네스 자체의 Python 3.9 최소 요구와 다르다.
- `mcp-solver-serve`는 stdio 서버이며 호스트 모델이 추론한다. 서버 자체는 AI API 키를 요구하지 않는다.
- SAT/MaxSAT/SMT/CP/ASP/DP 계열 백엔드 선택과 Python 커널 실행을 제공한다.
  라이브러리 동적 취득·캐시·프로세스 생성 때문에 설치 공간·네트워크·실행 권한을 확인해야 한다.
- **동명 PyPI 패키지를 바로 설치하지 않는다.** 조사 당시 README는 PyPI 이름이 제3자의 오래된 v2에
  묶여 v4를 PyPI로 제공하지 못한다고 명시했다. 상태가 바뀌었는지 공식 원문을 다시 확인한다.
- 원문이 안내하는 소스 checkout 기반 서버 명령은 다음 형태다. 검토한 커밋에 고정한 checkout에서,
  환경이 허용할 때만 사용하며 아래 경로는 실제 경로로 바꾼다. 이번 작업에서는 실행하지 않았다.

```bash
uv run --project /path/to/mcp-solver --extra agent mcp-solver-serve
```

- 별도 `mcp-solver` CLI/벤치마크는 외부 OpenRouter 모델을 쓰는 경로다. 제공 Codex용 연결로 사용하지 않는다.
- `submit_code`의 문법 확인은 문제 의미와 답의 정확성을 독립적으로 증명하지 않는다.

### 3. mcp-optimizer — 비교 후보, 실행 검증 전 채택 보류

- [저장소](https://github.com/dmitryanchikov/mcp-optimizer), MIT, 조사 커밋의 버전 0.4.1.
- Python >=3.11, FastMCP·OR-Tools·PuLP 등을 의존하며 README는 stdio/SSE 구성을 안내한다.
- 문서의 macOS 설치·솔버 의존성 예외 때문에 기본 경로로 고정하지 않는다.
  원문의 시스템 경로 생성·관리자 권한·라이브러리 심볼릭 링크 우회는 적용하지 않는다.
- 플랫폼과 솔버를 고정한 재현 검증 후에만 채택 여부를 정한다. README의 테스트 배지는 우리 실행 증거가 아니다.

## 환경별 실행 기준

| 실제 환경 | 진행 |
| --- | --- |
| 라이브러리 실행 가능 | 설치된 버전 확인 → 작은 알려진 정답 → 실제 모델 → 독립 검증 |
| 로컬 MCP 등록·프로세스 실행 가능 | 제공 환경 내부 stdio 후보 검토 → tools/list → 작은 문제 호출 → 결과 검증 |
| 파일 읽기만 가능/프로세스 실행 불가 | 문서형 설계·검수만 진행, 계산·설치·MCP 활성화는 미실행 표시 |
| 인터넷·설치 제한 | 이미 제공된 도구 또는 표준 라이브러리 기준선 사용. 제약·성능 한계 기록 |

원격 개인 서버에 문제·코드·데이터를 보내지 않는다. 외부 AI 키를 연결하거나 읽기 전용 권한을
우회하지 않는다. 현재 시험의 허용 범위가 우선이다. MCP 추가는 별도 설정 작업이며 이 패키지를
설치하는 것만으로 서버가 등록되거나 실행되지는 않는다. MCP 서버의 전체 코드 보안 감사도 미수행이다.

## 최소 검증 사례와 판정

아래 숫자는 연습용 기대값이다. 이번 조사에서 실행한 결과가 아니다.

| 종류 | 연습 입력 | 별도로 확인할 기대값 |
| --- | --- | --- |
| 기호식 | 실수 x에 대해 x²−5x+6=0 | 해 2,3을 원식에 대입해 0. 분모·정의역 제한이 있는 식은 추가 검증 |
| LP | x,y>=0, x+y<=4, x<=2, max 3x+2y | x=2,y=2, 목적값10. 모든 제약과 목적값 직접 재계산 |
| 정수/논리 | 정수 x, x>=0, x<=2, x>2 | 불가능. 시간 초과/unknown을 unsat로 처리하지 않음 |
| 경로 | A→B=2,B→C=3,A→C=9 | 최소 비용5. 방향·경로 유효성·도달 불가 사례를 별도로 확인 |

실제 과제에서는 다음을 근거에 남긴다.

- 문제 모델: 변수·단위·경계·강제/선호 제약·목적함수, 입력 전처리와 누락/중복 처리.
- 비교: 단순 기준선, 작은 완전 탐색 정답 또는 수작업 정답과 대조. 검사기는 원래 요구에서 독립 작성.
- 상태: feasible와 optimal, infeasible와 timeout/unknown, 목적값과 bound/gap을 구분.
  API마다 상태 이름·보장 수준이 다르므로 해당 버전 문서를 확인한다.
- 재현: 라이브러리/솔버 버전, 입력 식별자, 시간 제한, seed/병렬 설정, 실행 시간, 메모리 등 필요한 측정값.
- 민감도: 입력 한 요소를 바꾼 실험과 복합 변경을 구분하고 변화 원인을 관측으로 확인한다.
  예를 들어 최소화 문제에서 제약만 강화하면 진짜 최적값은 개선되지 않지만,
  시간 제한 휴리스틱의 관측값은 달라질 수 있다. 이 성질을 무조건 테스트 합격 조건으로 쓰지 않는다.
- 서비스: 계산 성공과 결과 적용 성공을 분리한다. 실패·시간 초과·중복 요청·재시작 시 실제 상태와
  기존 적용 결과의 처리 정책을 검증한다. 특정 큐·DB·분산 시스템을 무조건 추가하지 않는다.

## 설명·리뷰·완료 근거

`요구 → 수학 모델 → 선택/미선택 이유 → 실제 실행 상태 → 독립 검증 → 한계` 순서로 설명한다.
Sol A/B는 같은 입력·코드·측정 결과를 받고 서로의 첫 결론 없이 모델 누락과 검증 빈틈을 검토한다.
두 모델의 동의는 수학적 증명이나 솔버 실행의 대체물이 아니다. 관측하지 않은 결과는 미검증으로 남긴다.
외부 도구 설치 없이 이 가이드를 읽고 적용할 수 있다. 현재 Probe에서의 설치·MCP 연결·실행은 미검증이다.
