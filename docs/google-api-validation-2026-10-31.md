## 실제 Sol 호출

각 호출은 새 CLI 프로세스, `gpt-6.1-sol`, `read-only`, 승인 `never`였다.
effort는 지정하지 않았고 로컬에서 관찰된 기본값은 `low`였다.
리뷰 A/B는 같은 파일 상태를 받았으며 서로의 결론이나 부모 대화 이력을 받지 않았다.

세 호출 모두 과제 파일·Git 상태가 유지됐으며 종료 뒤 캐시 디렉터리도 없었다.
설계 호출의 설치 디렉터리 조회는 예상된 부재로 종료 1이었다. 오류를 숨기지 않고 직접 읽기를 유지했다.
리뷰 검사 스크립트의 종료 0은 관찰 완료를 뜻하며 심어 둔 결함의 통과가 아니다.
Go 스타일의 NOT_APPLICABLE도 Python 스타일/API 통과로 바꾸지 않았다.
합성 파일에 기존 `/tasks` 조회 handler·실제 HTTP 라우터가 없어 그 충족은 확인 불가/누락으로 보고됐다.

## 유지보수 검사와 한계

기존 자동 테스트 42개가 11.999초에 통과했다. Skill validator, TOML 파싱, 새 로컬 링크,
원문 해시, diff 공백 검사도 통과했다. 독립 Sol 두 정적 검토에서 API 의미나 연결 결함은 발견되지
않았고, 한 검토가 찾은 출처 문서의 AIP 개수 오기는 18개로 고쳤다.

이 실험은 architect와 코드 리뷰 A/B의 실제 읽기·적용을 확인한 것이다. 나머지 역할의 새 API
분기는 경로 검토만 했으며 13개 전체 흐름 실행이나 모든 가능한 API의 정확성을 증명하지 않는다.
