## 재수집 분기

| 상황 | 실제 순서 | 판정 |
| --- | --- | --- |
| R1: 출처가 비어 있고 API 설명도 틀린 첫 수집물 | evaluator → collector 재수집 → 새 evaluator의 원문 재대조 | 최초 주장 기각, 보완 설명 조건부 채택 |
| R2: 허용 자료에 내부 측정 근거가 끝내 없음 | collector → evaluator → collector 재수집 → 새 evaluator | 채택 0건·보류, 총 2사이클·재수집 1회에서 중단 |

R1은 “`is_relative_to()` 자체가 심볼릭 링크를 해소하고 안전한 경로 포함을 보장한다”는 모의 주장이었다.
실제 collector는 공식 문서를 열어 자료를 보완했고, 새 evaluator도 독립적으로 원문을 열었다.
`is_relative_to()`의 문자열 관계 검사와 `resolve()`의 링크·`..` 해소를 구분했으며,
검사 후 파일시스템 변경까지 안전하다는 보장은 채택하지 않았다.
근거: [is_relative_to](https://docs.python.org/3.13/library/pathlib.html#pathlib.PurePath.is_relative_to),
[resolve](https://docs.python.org/3.13/library/pathlib.html#pathlib.Path.resolve).
실제 웹 도구 호출은 재수집자 3회, 최종 평가자 2회였다.

R2는 가상 칩의 “처리량 2배”라는 주장만 있고 측정 보고서·방법·저자·시점·원문이 없는 폐쇄된 inventory를 사용했다.
재수집 후에도 출처나 숫자를 만들어내지 않았고, 3번째 사이클 없이 보류했다.
각 수집/평가의 완료가 다음 단계 시작보다 앞선다는 것도 외부 컨트롤러가 런타임 시각으로 확인했다.

## 고위험 교차 검증 분기

공통 계약은 지정 루트 내부의 기존 일반 파일, 정확히 소문자 `.json` 확장자만 읽는 것이다.
각 케이스는 모의 A만 HIGH를 지적하고 모의 B에는 지적이 없는 상태에서 시작했다.
상대편 새 reviewer가 실제 코드와 입력을 확인했으며, 결론을 미리 강요하지 않았다.

| 상황 | 실제 확인 | 처리 |
| --- | --- | --- |
| H1: 문자열 접두사로 경로 경계 검사 | `../reports_extra/demo.json`이 루트 밖인데 반환됨, exit 0 | 재현됨, HIGH 유지 |
| H2: 해석된 경로의 포함 관계 검사 | 같은 입력을 `ValueError`로 거부, exit 1 | 해당 HIGH 지적 기각 |
| H3: 확장자를 소문자로 바꿔 비교 | `UPPER.JSON` 수용, exit 0 | 계약 위반은 보존, HIGH → LOW |
| H4: 구현이 없는 배포 adapter에 위임 | 위임 코드만 확인; 실제 구현·설정·실행 근거 없음 | 미확정·미해결 유지 |

H2의 기각은 해당 공격 입력에 대한 판정이며 파일 전체에 결함이 없다는 승인이 아니다.
H4에서는 가상 adapter를 만들어 실제 배포 취약점인 것처럼 재현하지 않았다.
최종 auditor도 H1–H3을 직접 재실행하고 원본 4개 파일의 지문을 대조했다.
