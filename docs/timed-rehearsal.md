로컬 macOS·Codex CLI 0.159.3에서 GitHub 아이디만으로 발견하는 첫 요청부터 실행했다.
시험용 새 작업 공간에서 시작했고 다른 로컬 저장소 사본이나 URL을 모델에게 주지 않았다.
공개에서 내려받은 테스트 대상 버전은 `70c7d64`다. 실제 Probe에 접속한 리허설은 아니다.

정상 신뢰 화면은 로컬 CLI TUI를 PTY로 조작했고 단계 사이의 진행 지연·공개 자료 조사 시간도
타이머를 멈추지 않고 포함했다. 반복 측정이나 모든 환경에서의 15분 완료 보장이 아니다.

Probe의 관리 제한을 바꾸거나 우회하는 방법으로 사용하지 않는다.

## 실제로 확인한 증거

- 정확한 공개 저장소의 계정 API 조회·Git clone과 내려받은 commit을 확인했다.
- `/hooks` 정상 화면에서 두 훅을 신뢰하고 새 세션에서 실행했다. 신뢰 우회 플래그는 사용하지 않았다.
- 같은 세션의 실제 SessionStart, 첫 Stop의 `decision: block`, verify 종료 코드 0,
  `stop_hook_active: true`인 다음 Stop의 허용을 추적 어댑터 기록으로 확인했다.
- 두 독립 CLI의 실제 시작부에서 서로 다른 session id와 PID, `gpt-6.1-sol`, read-only를 확인했다.
  관찰된 effort는 high였고 하네스에서 강제하지 않았다.
- A/B 둘 다 합계의 +1 오류·빈 입력 오류와 비소유자 접근 허용을 읽기 전용 명령으로 재현했다.
  임시 파일이 필요한 heredoc은 실패해 `python3 -B -c`로 바꿨다.
- 두 검수 전후 코드 지문이 같았고 리뷰 대상 파일도 변경되지 않았다.
- 마지막 보고 뒤에도 영수증이 현재 코드 지문과 일치했다.
- 테스트 프로세스를 종료하고 해당 임시 프로젝트·훅의 신뢰 항목만 정리했다.
  그 밖의 파싱된 사용자 설정은 보존했다.

정규화한 수치·판정은 [timed-rehearsal.json](timed-rehearsal.json)에 있다.
개인 경로·사용자 설정·원본 세션 로그·문제·인증 정보는 공개하지 않는다.

## 확인하지 못한 것과 수정

이번 메인의 네이티브 서브에이전트 요청은 모델 capacity에서 멈춰 지원 여부를 판정하지 못했다.
성공한 듀얼 리뷰는 **두 새 CLI 프로세스**이며 네이티브 서브에이전트 실측으로 바꾸어 설명하지 않는다.
실제 사람의 타이핑·Probe의 모델 큐·네트워크·쓰기 권한·브라우저 미리보기·제출·종료 UI는 미검증이다.

실행표에 초기 작업 권한·네트워크 확인, capacity 시 사용자 터미널 대체 경로,
리뷰 로그·종료 코드·지문을 메인에게 전달하는 절차를 보완했다.
실측 후 바뀐 실행표 전체를 다시 15분 측정한 것은 아니다.

실전 판단은 ‘15분이면 무조건 된다’가 아니라 **로컬에서 한 번 15분 내 완료했지만 여유가 작다**다.
실제 사전체험에서는 지연 시 미확인 항목을 남기고 정해진 시간에 종료한다.
