# MCP 불가 후 직접 계산 전환 검증

2026-11-05. mcp-optimizer 제외와 전환 계약을 반영한 새 설치본으로 수행했다.
버스 재출제 예측과 무관한 방정식 `x²−7x+12=0`을 사용했다.

## 실제 실행

독립 Sol CLI의 architect 역할에 요청·환경 사실만 전달했다. 예상 해는 요청에 넣지 않았다.
이전 네이티브 MCP의 승인 차단을 선행 근거로 제공했고, 합성 입력의 로컬 Python 계산은
별도로 허용했다. MCP 재등록·재호출·설치·파일 수정·권한 변경은 범위에서 제외했다.

- 새 설치본의 Skill·math-tools.md·읽기 전용 절차를 읽었다.
- 가상환경 Python에 `-B -c`로 SymPy를 직접 호출했다.
- Python3.13.14 / SymPy1.14.0, 실제 해 `{3,4}`, 별도 정수 연산의 대입 잔차 `{3:0,4:0}`.
- 기준 문제의 해 `{2,3}`와 인수 전개도 확인했다. 실제 계산 명령 종료코드0.
- MCP 실패와 직접 계산 성공을 구분했고, MCP 차단을 성공으로 바꾸어 기록하지 않았다.
- 계산 자체가 금지된 환경에서는 전환하지 않고 미실행으로 보고한다고 응답했다.
  이 마지막 항목은 지침 판단 확인이며 프로세스 금지를 새로 설정해 실행한 시험은 아니다.

[실제 Sol 응답](fallback-sol.md)과 [실행 메타데이터](fallback.json)를 함께 보관한다.
이 추가 검증은 새 지침의 직접 호출 행동 확인이다. 앞선 A/B 리뷰를 이번 변경의 신규 듀얼리뷰로 재표시하지 않는다.

## 패키지 미가용 분기도 관측

첫 요청을 준비할 때 테스트 작성자가 가상환경 실행 경로의 심볼릭 링크를 해석해
기본 Python 경로로 전달했다. 그 환경에서는 SymPy import가 실제로 실패했다.
Sol은 설치하지 않고 표준 라이브러리 `math.isqrt`·`Fraction`으로 해3·4와 잔차0을 확인했으며,
이를 SymPy 성공으로 보고하지 않았다. [첫 실행 응답](fallback-stdlib-sol.md)에 보존했다.
이후 가상환경 진입 경로를 그대로 전달해 위 SymPy 직접 호출을 새 세션에서 검증했다.
첫 실행 실패를 라이브러리 자체 결함으로 해석하지 않는다.

## 패키지 검사

- `python3 -m unittest discover -s tests -v`: 42개 통과, 11.989초.
- Skill quick_validate: 통과.
- 설치된 선택 목록: 라이브러리7개·MCP2개. mcp-optimizer는 활성 tools에 없고 제외 이력에만 존재.
- 새 설치본의 Skill·전환 가이드·workflow·읽기 전용 문서·역할13개가 배포 template와 일치.
- JSON·TOML 파싱 및 변경 문서의 로컬 링크 확인.

이것은 에이전트가 지침을 읽고 실행한 결과다. 별도 자동 MCP 프록시·권한 우회·라이브러리 설치 훅은 없다.
실제 Probe 설치·직접 실행 권한·해당 환경의 라이브러리 가용성은 계속 미확인이다.
