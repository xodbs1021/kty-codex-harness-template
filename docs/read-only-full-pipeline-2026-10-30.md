## 합성 과제

웨이퍼 판정 JSON을 읽어 합격 비율을 계산하는 작은 Python 분석기다. 실제 시험 문제가 아니다.
초기 안내에는 null의 업무 의미와 분모 0 처리를 비워 두었다. 사용자가 판단을 보유한다고 명시했다.
초안 코드에는 결측값 분모·빈 입력·스키마 거부·경로 탈출의 결함이 있고, 테스트는 이를 드러내도록 준비했다.
경로 검증·행 검증·계산 경계 분리, 신뢰하지 않는 파일명, 회귀 테스트 요구로 설계·보안·테스트 역할이 필요했다.

clarifier 결과를 받은 **이후에** 사전 작성된 모의 업무 담당자 답변을 읽었다.
이는 실제 사용자나 운영진의 응답이 아니다. 질문과 답변의 실제 시간을 런타임 기록에서 대조했다.
기존 코드의 diff도 테스트 컨트롤러가 실행 전에 준비한 것이며 읽기 전용 에이전트의 변경이 아니다.

## 발견한 문제와 보완

1. **zsh heredoc의 임시파일 생성 시도.** 첫 후보 실행에서
   `can't create temp file for here document: operation not permitted`가 발생했다.
   쓰기 성공 근거는 없고 전체 파일 비교도 동일하지만, 쓰기 시도가 전혀 없었던 것은 아니다.
   메인이 권한을 바꾸지 않고 `python3 -B -c`로 한 번 재시도해 12개 검사를 통과했다.
   이후 read-only 지침에 heredoc/here-string을 피하고 쓰기 없는 인자 전달을 사용하도록 추가했다.
2. **읽기 전용 developer의 역할을 명시.** 이번 요청의 제약에 따라 실제로는 응답 후보를 만들었지만,
   기본 역할 문서에도 후보 작성·미적용 표시·메모리 검사와 디스크 검사의 구분을 추가했다.
   후보 식별자·지문을 다음 검사/리뷰/설명에 전달하도록 보강했다.

위 보완은 전체 리허설이 끝난 후 반영한 지침 변경이다. 보완된 문서로 17호출 전체를 다시 돌렸다고 주장하지 않는다.
